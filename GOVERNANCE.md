# Governance

Agent Engineering Toolkit uses a maintainer-led open-source model.

## Roles

- **Primary maintainer:** owns releases, security coordination, roadmap arbitration, repository governance, and final merge decisions.
- **Maintainer:** trusted contributor with sustained review/triage/release responsibility.
- **Contributor:** anyone proposing code, tests, documentation, issues, or reviews.

## Decision principles

Decisions favor portability, maintainability, evidence, least permanent context, deterministic validation, and clear external-effect boundaries. Compatibility claims require observed evidence on the claimed surface.

Routine changes are decided in pull requests. Material changes to the portable contract, licensing, security model, or skill activation policy should include an architecture note in the PR and update the relevant docs.

## Maintainer activity

Maintainer responsibilities include issue triage, PR review, release management, compatibility tracking, security response, provenance review, and keeping skills aligned with current upstream platform documentation. This activity is intentionally visible in GitHub issues, pull requests, releases, and changelog entries.

## Adding maintainers

A contributor may be invited as a maintainer after a sustained record of technically sound contributions and review behavior. There is no contribution quota.
