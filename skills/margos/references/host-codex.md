# Codex host adapter

Use Codex's native subagent surface; do not add an MCP server or background runtime for MARGOS. When the current host exposes child model or reasoning controls, bind the MARGOS compute class to the lowest sufficient proven child capability.

- `ECONOMY_READ`: prefer a read-focused/explorer child with the host's current fast or economical model option.
- `BALANCED_EXEC`: use an execution-focused worker with the host's standard coding capability and task-appropriate reasoning.
- `FRONTIER_REASONING`: use a fresh child with the strongest available reasoning configuration only after escalation signals are met.
- `INDEPENDENT_CRITIC`: prefer fresh read-only context so critique is independent from the implementer.

Exact model names are host state, not MARGOS policy. If Codex exposes only the parent model, run the obligation directly rather than pretending a tier change occurred. Do not create or modify project/global Codex profile configuration unless the user separately asks for that effect.
